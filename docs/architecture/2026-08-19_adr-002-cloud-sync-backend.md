# ADR-002：云端账户、同步与协作后端边界

| 字段 | 内容 |
|------|------|
| 日期 | 2026-08-19 |
| 状态 | Accepted for future phase |
| 决策者 | Deskforge 项目 |

## 背景

Deskforge 当前是 Electron Main + SQLite 的本地单机应用。未来需要跨设备账户、同步、消息和多人协作，但不能破坏离线能力，也不能把数据库直接暴露给 Renderer。

## 决策

未来云端服务优先采用 **TypeScript + NestJS/Fastify + PostgreSQL**，本地 SQLite 继续作为离线主数据副本。客户端通过 HTTPS API 和 WebSocket 与服务端通信，使用短期访问令牌、可轮换刷新令牌和设备会话。

如果后续 AI 工作负载较重，Python 仅作为独立模型服务；如果团队已有成熟 Java 基础设施，可将云端 API 替换为 Spring Boot，但不在客户端内嵌 Java 运行时。

## 数据同步原则

```text
本地操作 → SQLite 业务事务 + outbox → HTTPS 增量上传
云端变更 → 游标拉取/推送 → 冲突策略 → SQLite → UI
```

- 每条同步实体具有 `server_id`、`version`、`updated_at`、`deleted_at`。
- 本地写入与 outbox 必须同一事务。
- 服务端使用幂等键防止重复提交。
- 简单字段先用最后写入胜出；任务状态、成员和文本冲突保留审计记录。
- 消息使用独立会话/消息模型，不复用通知表。
- 用户可以退出云端账户而不丢失本地数据，并可撤销其他设备。

## 服务端边界

| 模块 | 责任 |
|------|------|
| Identity | 注册、登录、MFA、刷新令牌、设备撤销 |
| Workspace | 成员、角色、邀请与权限 |
| Sync | 增量游标、幂等写入、冲突记录 |
| Messaging | 会话、消息、已读回执与 WebSocket |
| Update | 公共 HTTPS 安装包、元数据和分阶段发布 |
| Audit | 安全事件与关键业务操作日志 |

## 启用前置条件

- 域名、TLS、云数据库和对象存储。
- 正式运营主体、隐私政策、用户协议和数据处理清单。
- 邮件/短信验证渠道及安全告警。
- API 威胁建模、限流、备份、监控和灾难恢复。

当前版本不连接任何云端服务，AI 建议和消息继续显示“正在开发中”。
